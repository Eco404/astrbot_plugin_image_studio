# ComfyUI 接入

本轮使用原生 HTTP/WebSocket 接口，不依赖额外的 ComfyUI API 代理或 SDK。Provider 表示服务器实例，其下工作流条目保存可执行 API 图、可选界面图、输入绑定和结果节点。

## 执行与配置

- 从 API JSON、保留 prompt 元数据的图片或图库导入工作流；仅有界面图时明确要求导出 API 格式，不使用图库的参数猜测结果作为执行图。
- 模板可以保持固定输入原样运行，也可以绑定提示词、反向词、数值、枚举、图片及蒙版。绑定只能修改明确的值输入，不直接覆盖节点连线。
- 在线检查目标服务器的节点类型、输入字段、模型选项及输出能力。模型替换须由用户明确选择，不自动下载模型、安装节点或跳过依赖。
- 一个工作流可能有多个输出节点和批次。单次计划出图数由模型配置的「工作流单次出图张数」明确给出，不从节点 batch_size 推测。
- count 表示本次目标总张数，插件据此拆为可恢复的子任务，按模型和服务商并发限制提交。每轮超出计划额度的结果截断，不足不补跑，最终按子任务和输出顺序汇总为一个图组。旧 count 节点绑定转换为普通输入；已提交旧任务仍按其原执行策略恢复。
- 输入图上传后使用服务端返回名称。蒙版绑定到原生 LoadImage 时，白色重绘、黑色保留，通过反向 Alpha 适配 MASK 输出。
- 未开放主提示词绑定时允许空提示词，其他 Provider 的必填规则保持不变。

## 历史与任务

工作流定义由模型配置持有。提交时记录不可变修订、请求值、输入文件与连接地址指纹。历史图片另保留实际执行图与绑定信息，修改模板不影响旧记录。

任务在服务器排队和执行时独立于浏览器连接。WebUI 通过本地任务 ID 查询状态；WebSocket 提供进度，history 查询确认完成与结果。重启恢复已登记任务：已有远端编号时查询原任务，尚未提交的子任务可以继续提交；提交中断但未取得编号时标记 unknown，不自动重提。已取得编号的失败任务可以继续查询同一任务。

取消使用定向任务接口，旧版只删除指定排队任务，不能保证停止运行中的任务；从不使用全局中断。

API 图同时保留精确 JSON 文本，避免浏览器将 64 位种子四舍五入；固定输入修改通过显式覆盖项合并。

## 随图保存的界面工作流

`ui_sync.py` 在上传参考图、应用本次输入后，以最终执行图同步当次界面工作流副本。同步目标来自两部分：固定输入覆盖项规范化后保留的 `workflow_sync_targets`，以及 `prepare_graph(..., written_inputs=...)` 本轮实际写入的绑定目标。位置记录只保存节点、字段和节点类型，不保留待重放的旧值，避免覆盖新的运行参数。

节点 ID 和类型、控件布局、连接状态必须匹配。标准节点及已验证的 rgthree / LoadImage 控件按明确布局定位；具名控件字典按字段名定位。未知布局、重复节点、由连线提供的输入等保留原值并产生可见警告，不从 API 字段顺序或碰巧相同的值推断控件位置。同步不修改模板、其他控件、布局或未修改的显示快照，不为仅有 API 图的配置推导界面图。

插件绑定的 `-1` 在提交前解析为具体随机种子；rgthree 固定 `-1` 同步到界面控件后交给节点生成并回写实际种子。对已知 rgthree 服务端特殊值 `-1/-2/-3`，执行准备阶段始终登记其种子同步目标，以兼容旧模板并满足节点的特殊值回写条件。返回图片字节保持原样，不能用提交前的快照覆盖节点在服务器端写入的结果。旧版配置中其他已消费且丢弃的固定覆盖项无法可靠追溯，需重新编辑对应字段后建立修改记录；不以整图差异自动补记。

## 数据库

插件 1.3.0 使用正式数据库 v3（`PRAGMA user_version=3`），通过一次 `v2 → v3` 迁移新增 `comfy_workflow_revisions`、`comfy_jobs` 及索引。新库直接创建最终结构；最终 `3-dev.1` 开发库核验后移除 `schema_meta`，保留现有任务与修订，不重建业务表。已有库转换前备份，失败回滚，重复启动不重复迁移。完整兼容范围和恢复方法见 [开发与发布维护](DEVELOPMENT.md)。

输入及结果临时文件由任务持有，浏览器刷新不释放运行中输入。工作流修订不写 Provider 密钥；实际认证取当前 Provider 配置。变更服务器地址后不会把旧任务误交给新服务器。

完成任务的私有输入与结果缓存保留 7 天，运行中及状态不确定的任务不参与此项清理。缓存到期后，只能从仍保留在图库中的对应原图恢复结果；图库图片已经删除时会明确提示不可用，不重新生成。工作流历史同时保留参数结构，当前仍存在的同名参数继续遵循当前显示、记录与回填设置。

## 范围与验收

首版只处理图片。暂不包含任意界面图转换、任意第三方节点协议转换、自动安装依赖、视频音频结果或逐像素一致保证。

离线验收覆盖 API 图导入/绑定、依赖缺失、模型替换、64 位种子、输入顺序、蒙版、任务恢复、重复提交保护、多输出与部分失败、迁移回滚及 WebUI。

2026-09-15 在用户提供的 ComfyUI 0.34.0、RTX 5090 实例上进行了隔离测试（当时的开发版本）：

- 标准 SDXL 工作流，512×512、8 步，文生图成功，两个 SaveImage 输出均保留（约 6.03 秒）。
- 将其中一张结果上传，经 LoadImage → VAEEncode 执行 4 步图生图成功（约 1.55 秒）。
- 修改当前模板后，已保存历史的实际执行图保持原样。
- 使用当时的数量绑定策略，原生批次为 1、请求数量为 2，产生两个不同远端任务并均完成；插件只写入一个包含两张图片的图库图组。后续改为手工配置单次出图数，其截断、不补跑和旧任务兼容另由离线回归验证。
- 内网与 HTTPS 反代均可连接；同一任务的历史查询、原图下载哈希一致，WebSocket 均收到状态事件，结束时队列为空。

以上耗时只记录本次基础工作流。任意第三方节点、特定复杂工作流及真实服务重启/取消故障场景不由这些测试保证；恢复、取消和蒙版变换另有离线测试覆盖。
