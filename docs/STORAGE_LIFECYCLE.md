# 存储与维护

插件 `1.4.0` 的存储优化及图组标题使用正式数据库 **v4**，以 `PRAGMA user_version=4` 标记，不保留 `schema_meta`。旧版插件不能直接读取这套结构；升级、备份及回退要求见 [开发与发布维护](DEVELOPMENT.md)。

## 图片目录

运行数据仍由 `StarTools.get_data_dir` 定位，本地图片使用以下布局：

```text
data/plugin_data/astrbot_plugin_image_studio/
  history.sqlite3             图库、资产关系及 ComfyUI 任务数据库
  images/
    assets/                   原图及参考图
    thumbnails/               本地与外部图库的预览缓存
  comfyui_blobs/              ComfyUI 共享输入、输出缓存
  backups/                   数据库升级备份
```

`backend/database/migrations/images_layout.py` 负责将旧 `history/assets`、`history/thumbnails` 中已登记的文件迁入 `images/`。首次启动先预检源、目标路径的内容冲突和符号链接，校验文件后以硬链接或复制准备新目录，再在同一数据库事务中更新 `image_assets`、`image_thumbnails` 及 ComfyUI 结果中明确的图库路径。写事务覆盖文件准备阶段，整个迁移另由进程锁串行化；该流程发生在后台任务和普通图库维护启动之前。事务提交后才删除已校验的旧副本和空目录。

迁移日志 `.images-layout-migration.json` 保存文件清单与内容摘要，中断后再次启动会结合数据库中的路径重新核验并续跑，成功清理旧副本后移除日志；相同内容的目标文件可以复用，不覆盖内容不同的目标。旧 `history/` 下其他文件不属于本次迁移，保留原位。存储统计兼容新旧目录，避免迁移中断时遗漏文件占用；共享硬链接的实际分配空间仍只计算一次。

这是图片布局与持久路径转换，数据库文件名仍为 `history.sqlite3`，目录迁移不增加结构修订；当前数据库为 v4，插件版本为 `1.4.0`。外部图库原图路径不迁移，资产和图片编号保持原值。升级前仍应备份完整数据目录；回退时同时恢复代码、数据库和图片布局。

## 正文与投影

`storage_payloads` 按内容保存 JSON 正文，较大且适合压缩的内容使用 zlib，记录编码、原始大小和内容摘要。读取时限制展开大小并验证摘要。工作流采用专门编码：当对象与对应 `*_json` 文本一致时只持久化原文本，读取时重建对象。原始文本、64 位种子和不一致的旧表示均不被静默改写。

`storage_payload_refs` 以表名、记录 ID 和内部位置记录所有权。同一快照可以同时被任务和图库引用；删除一个 owner 只解除该 owner 的引用，所有引用都解除后才回收正文。owner 的删除触发器与业务删除处于同一 SQLite 事务。内部标记只在明确的仓储字段边界展开，不递归解释任意用户参数。

工作流修订继续不可变保存，任务请求通过已有 `revision_id` 恢复配置。逐图实际快照被父任务、子任务和图库共享；实际执行的种子、参考图文件、输入绑定、参数 schema、输出选择和界面图仍全部保留。模板和实际执行图不能仅凭相似结构合并。

元数据保留轻量规范参数，将 raw 和重型解析证据分开持久化。普通列表、图片序列和 manifest 不解压这些正文；详情和导入编辑按需恢复。手填覆盖单独保存，缺少编辑来源的旧记录保守保留完整值。图组能够引用首图的同源派生字段，不复制整份节点证据。

任务队列读取显式状态列，不为了进度显示解析工作流。图库的模型、模式和图片时间有轻量投影，图组维护最新内容时间。所有生成、导入、编辑、删除及外部扫描写入都会刷新投影，排序不再逐组提取大 JSON。

搜索只采集面向用户的提示词、模型、参数及来源相关字段，去重后保存。工作流正文、匹配指纹和内部缓存标记不进入搜索；旧的未使用 FTS 表在迁移时清退。

## ComfyUI 文件和任务

新输入/输出保存在按 SHA-256 寻址的 `comfyui_blobs`，父子任务复用同一文件。旧 `comfyui_inputs`、`comfyui_outputs` 文件在维护时验证内容后转为共享引用，提交新引用后才移除旧入口。图库图片仍由图库资产仓储管理。

结果可靠落入图库后，任务描述绑定对应的图库图片，而不是继续保存完整重复原图。读取结果会验证图组、图片、顺序及内容关联；用户删除图片后，不通过其他图组碰巧相同的文件恢复它。删除图组或单张图片提交后，通知任务仓储解除已经安全结束的任务对已移除结果的缓存和快照引用；启动与定时维护也会核对旧清单。共享文件只有在所有任务引用解除后才回收，仍有图库关联但文件暂不可用的情况不视为主动删除。

默认恢复窗口为 24 小时：

- 执行中或提交结果未知的任务保留必需资源，不自动重提。保护沿父子关系双向传播，避免子任务已结束就提前丢失批次恢复数据。
- 窗口内失败任务仍可按已有远端编号恢复；若仅继续获取远端结果，不因已经无须再次上传的参考图缺失而重复提交。
- 超过窗口且不受依赖任务保护的终态任务归档，关闭过期恢复入口、解除大正文引用，保留必要摘要、远端编号和幂等指纹。
- 归档修订可以只保留轻量记录；新请求再次使用相同修订时重建正文。图库持有的实际快照独立保留，归档不影响历史复现。

任务从队列隐藏与归档是不同操作。未知提交不会通过隐藏、过期或恢复操作重新发送到远端。

## 统一维护

启动、每小时定时维护和手动维护共用入口，以互斥锁避免重复执行。先整理 ComfyUI 任务，再处理导入暂存和图库维护，最后回收无引用正文。普通维护不压缩整个数据库。

已有临时文件期限保持：参考图暂存 24 小时；导入、导出和发送暂存 1 小时。资产的临时保留期限与会话访问关系继续分开：临时保护结束不会撤销仍存在原图的会话授权。新安装的历史最大记录数、最大图片容量均为 0（不限制），已有显式配置保持不变。导入记录、收藏与外部来源的图库配额豁免规则不变。

升级备份仅对名称和数据库内容均可确认的插件备份轮换，默认保留最近 3 份并保护本次迁移生成的备份。未知、损坏、未来版本或符号链接文件不会被自动删除。长期归档应独立保管完整数据目录。

手动深度维护在数据库空闲页至少 16 MiB 且占比至少 20% 时尝试回收文件空间；待处理或状态未知的 ComfyUI 任务、空间不足和锁竞争会使其暂缓。删除正文后尚未收缩的空闲页仍可被后续写入复用，不代表残留业务数据。

存储健康按原图、缩略图、ComfyUI 缓存、数据库、备份、其他暂存和其余文件显示内容大小，同时显示文件系统实际分配空间。ComfyUI 缓存汇总任务输入、任务输出和共享图片，后端保留细分类统计；数据库项以“大小（可回收大小 可压缩）”附注空闲页面，不单独列可复用空间。共享硬链接的磁盘分配只计算一次，不跟随符号链接。图库配额仍只按它负责的资产口径计算，磁盘总量不替代原配额。

## 迁移与验证

迁移保留已发布的 v1、v2、v3 升级路径及已支持的最终开发库转换。先使用 SQLite Backup API 生成一致性备份，再取得写锁重新校验状态；结构、正文引用和版本标记原子提交。无法解析的旧记录或校验失败会中止并回滚，不能以空对象覆盖损坏数据。

正式 `v3 → v4` 的正文转换固定在 `backend/database/migrations/v4_storage.py`，沿用 4-dev.1 阶段冻结的格式契约。该模块只依赖数据库的既有正文格式，不调用当前 Gallery/Provider 编码或解析器；今后调整日常编码逻辑不会间接改变旧库升级路径。事务控制、DDL 和正式版本标记由 `schema.py` 管理。

正式 v4 包含 `generations.title TEXT NOT NULL DEFAULT ''`，从旧正式库升级时与存储结构和正文转换一并提交。标题不进入工作流正文或图片解析投影，更新只涉及图组记录，搜索直接读取该列；旧图组默认空标题。

最终开发库 4-dev.2 已包含完整业务结构。正式化时核验并备份，只删除 `schema_meta` 并设置 `user_version=4`，不重复转换正文或修改标题，失败回滚。较早的 4-dev.1 必须先用末版开发代码（提交 `6153f83`）升级到 4-dev.2；正式版不猜测或修补未支持的开发布局。

数据库结构与正文迁移本身不删除或改写图片。`images/` 布局迁移在首次初始化时执行，按“准备目标文件 → 原子更新路径 → 清理已校验旧副本”分阶段推进；ComfyUI 旧缓存转为共享文件属于后续维护。迁移前应备份完整目录以支持回退。新库、升级库的最终结构一致，重复初始化不重复转换。

验证应同时覆盖：正文和精确 JSON 往返、引用共享及 owner 删除、人工覆盖、旧数据迁移与失败回滚、图片布局迁移中断续跑与冲突保护、过期/未知任务依赖、幂等恢复、图库删图后的结果读取、轻量查询和存储健康界面。仅有文件大小下降不足以证明迁移正确。
