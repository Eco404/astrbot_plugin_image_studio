# 图片导入与画廊管理实施计划

> 历史开发记录：以下计划与验证数量描述的是首次发布前的开发阶段，不代表当前版本状态。1.0.0 之后的现行规则见 [开发与发布维护](DEVELOPMENT.md)。

## 范围和约定

- 仅修改 Image Studio，保留现有 Agent 资产租约和投递边界。
- 图片文件及原始元数据保持不变；请求快照、解析结果和人工补充分开保存。
- 支持 NovelAI、ComfyUI、A1111/Forge 元数据与未知图片；本次不增加 ComfyUI/SD 生成执行器。
- 图片本体在用户确认后上传；此前仅在浏览器预览、提取元数据并请求解析。
- 导入与收藏不计入自动历史配额。收藏作用于整次生成；取消收藏后重新计入配额，保护 24 小时。
- 自动历史按生成记录计数、按共享资产去重计费；共有原图/参考图/缩略图不重复保存。
- 数据库从 `1-dev.1` 建立开发基线；正式发布合并当期开发迁移，不删除已发布版本迁移。
- 真实 `data/image` 和 `data/plugin_data/data1` 仅作只读样本，不清理旧开发文件。

## 验收重点

- 保留原始工作流文本、大整数 seed、请求尺寸与图片实际尺寸的差异。
- 自动选择模型只在唯一匹配时生效；无法映射的值明确显示，不自动生成。
- 导入幂等重试，失败卡片仍可编辑和重试，未知参数允许为空。
- 取消收藏、共享引用、租约、部分删除与整批删除不会误删其他记录的资产。
- 删除第一张后封面仍可见，详情和全屏查看顺序保持一致。
- 配额达到 90% 时最多标记 10 条真实清理候选；预警和清理使用同一规则。
- 分页调整保持浏览位置；保存草稿不因切换页面丢失。
- 1440/1100 桌面与 390/360 手机视口下无横向溢出、遮挡和滚动穿透；浅深主题均验证。

## 发布整理

正式数据库版本使用 `PRAGMA user_version`；开发目标和修订存入 `schema_meta`。
正式版拒绝未知开发修订。首次发布生成 v1 建表基线；后续每个数据库正式版本只保留一个从前一正式版本升级的迁移。
升级后的结构应与同版本新库一致，事务成功后更新版本标记；元数据回填独立、可重试。

- 静态检查：Ruff 格式检查、`F,E9` 错误检查、两份应用 JavaScript 语法检查、Git 空白检查通过。
- 未执行真实上游生图或实际聊天平台投递；这次改动未调整 LLM 工具契约。
